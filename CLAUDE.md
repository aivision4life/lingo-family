# CLAUDE.md — Instructions for AI coding assistants

This file is read automatically at the start of every session. Follow it strictly.
**What** to build is in `SPEC.md`. **How** to build it is described here.

## Project in one paragraph
A family-only PWA for learning **Korean and English** vocabulary, phrases and pronunciation, picture-first (every word, phrase and example sentence has an image).
Chinese was removed from the product on 2026-10-08 and from the code/DB in M1.6 — don't add `zh` code back.
Frontend: React + TypeScript. Backend: one Cloudflare Worker (serves the SPA and `/api`), D1 database, R2 media storage.
External: Azure Speech (TTS + Pronunciation Assessment), an LLM API (Gemini) for enrichment, Cloudflare Workers AI (FLUX) for images. Hosting must stay on free tiers.

## Commands
- `npm run dev`: Vite dev server on http://localhost:5173 — SPA + Worker (`/api/*`) with local D1/R2 (Miniflare, data in `.wrangler/state`). The Workers AI binding is removed in `vite.config.ts` for this command, so images come from the **fake provider** (`worker/services/fakeImage.ts`: fixed placeholder, `image_model = fake`, no quota). Needs `DEV_AUTH_BYPASS=1` in `.dev.vars`.
- `npm run dev:ai`: same with the real remote Workers AI binding (`vite --mode ai`); needs `cloudflared` (`winget install --id Cloudflare.cloudflared`) and a one-time Access login because the preview session runs on the Access-protected workers.dev domain.
- `npm run build`: typecheck (`tsc -b`) + production build into `dist/`
- `npm run preview`: build with `--mode preview` (production bundle + service worker, but no Workers AI binding), then serve it on http://localhost:4173. Use it to try the PWA; the service worker exists only in production builds.
- `npm run typecheck` / `npm run lint` / `npm test` (all tests: both vitest projects, ~70 s; `npm run test:watch` for watch mode). `npm run test:unit` runs only the `unit` project (src, shared, scripts, benchmarks: no Miniflare, a few seconds) for quick feedback while changing UI or pure logic. **Before every commit or deploy run the full `npm test`** (and `typecheck` + `lint`), not just `test:unit`.
- `npm run db:generate -- --name <short_name>`: create a migration in `db/migrations/` from `db/schema.ts`
- `npm run db:migrate:local` / `npm run db:migrate:remote`: apply pending migrations to D1
- `npm run cf-typegen`: regenerate `worker-configuration.d.ts` (the `Env` type) after editing `wrangler.jsonc` or `.dev.vars`
- `npm run deploy`: build + `wrangler deploy` (needs a real `database_id` in `wrangler.jsonc`, see M2)
- `npm run bench:images`: M1.8A image benchmark (Gemini image prompts + FLUX models), output in `benchmarks/report.html`
- `npm run migrate:content [-- --apply | --verify]`: M2.1 one-off move of local words/phrases/examples/Hanja/AI cache + R2 media to production (`scripts/migrate/`). Default is a dry run; `--apply` backs up production D1 into `backups/` first; `--verify` checks that profiles got cards. Production rows always win; profiles/cards/review logs are never moved. Local D1/R2 are read straight from `.wrangler/state` (the SQLite file name depends on `database_id`).
- `npm run scan-llm-content`: M2.11 one-off, **read-only** report of existing words/phrases/examples in production whose LLM-generated text `worker/services/contentCheck.ts` would flag (wrong script, e.g. a stray Latin letter in Korean). Lists only; never writes.
- `npm run topik-import [-- --apply [--force]] [-- --section reading|listening] [-- --source <name>]`: M6.1 one-off import of TOPIK reading questions from `.docx` files in `data/topik/` (gitignored, copyrighted — see below). Default is a dry run (prints a report); `--apply` backs up production D1 first, then inserts (skips a question that already exists unless `--force`). Imported rows start unverified; review them in Settings → TOPIK before they are used for practice. `--section` / `--source` limit the run by **file name** (same filter for the dry run and the apply; an unparseable file name always passes so it is still reported as an error). `--force` with no `--section` is **refused** before the backup and before any write, naming how many existing questions each section would be overwritten in — use `--section`, or `--all-sections` to confirm on purpose; without the guard, re-importing one listening file also resets `verified` on every reviewed reading question. The overwrite UPDATE names only `block`/`instruction`/`stem_text`/`stem_image_key`/`options`/`correct_option`/`warning`/`verified`/`updated_at`, so `id`, `segment_id`, `vocab*`, `explanation_vi`/`key_terms`/`explain_checked_at` and the question's cards/attempts survive it.
- `npm run topik-audio -- --exam <label> --intro <mark>`: M7.1/M7.20 — cut one listening paper's mp3 into clips. **`--intro` (where the spoken introduction ends) is required and has no automatic fallback**: `pickIntroEnd` was wrong on all 8 real papers in 4 different ways, and the reason is that nothing `silencedetect` measures separates a pause *inside* the introduction from the pause *before* question 1 (SPEC §11 M7.20). Run it once without `--intro` and it stops (exit 1, reads no D1, writes nothing) after printing the music-covered-introduction signal, a mark proposed from this paper's own reading speed (`estimateIntroEnd`), the self-check line next to it ("clip 1 would be 16.2s, question 1's text needs 15.7s" — a wide gap means the mark is wrong), the silences around it each with the `--intro` value to use, and **a 14-second sample cut at the proposed mark** (mark at second 6) in `data/topik-audio/_check/`. Listen, then run again with `--intro`. `--intro` without `--exam` is refused when several mp3s match: one mark belongs to one paper. Accuracy of the proposal is ≤4 ms against all 8 human-approved marks, which is **not** a reason to skip the listening step — the 8 failures all looked plausible too.
- `npm run topik-audio -- --link-only [--apply] [--local] [--exam <label>]`: M7.2 — attach newly imported listening questions to clips that **already exist and are already approved**. Touches nothing but `topik_questions.segment_id`: no mp3 is read (ffmpeg is never run), no `topik_audio`/`topik_segments` row is written, no approval is lost. `planLinks` (`scripts/topikAudio/plan.ts`) maps a question's *group* ordinal to a clip index — a group is a pair from question 21 on (`same_segment`, the Word file's CHUNG ĐOẠN mark), never one question per clip — and links nothing at all for an exam where anything disagrees: a stored link that contradicts the Word files, a needed clip the exam does not have, or numbering that does not run from 1. A question the Word file describes but `topik-import` has not inserted yet is reported as "not imported yet", not linked and not an error. Use it instead of re-running the normal `--apply --force`, which deletes the exam's audio row and cascades every clip away, nulling all existing links and throwing away the hand-checked boundaries.
- `npm run topik-groups [-- --apply] [-- --local] [-- --section reading|listening]`: M7.21 one-off backfill of `topik_questions.group_key` for questions imported before the column existed, read from the Word files' `CHUNG ĐOẠN` marks (the same `assignGroupKeys` the importer runs — never a second rule). Dry run by default; `--apply` backs up production D1 first. **Writes that one column only** — not `verified`, not `stem_text`, not even `updated_at` — which is why it exists instead of `topik-import --force` (8 columns, and un-approves what it touches). A row no Word file covers is reported as an orphan and left exactly as it is, never cleared. Idempotent: a second run reports 0 changes. Also reports groups whose members' stored `stem_text` has drifted apart, printing both.
- `npm run topik-speech-end [-- --apply] [-- --local] [-- --exam <label>]`: M7.6 one-off repair of `topik_segments.speech_end_ms` for clips cut before `mergeShortSegments` carried a short announcement's speech end over. Dry run by default (prints every clip of every exam: old, new, drift); `--apply` backs up production D1 first. **Writes that one column only** — `start_ms`, `end_ms`, the `topik_audio` row and `verified` are never touched, and each clip's new value is measured inside its own stored boundaries, so hand-reviewed boundaries survive. Needs ffmpeg and the exam mp3 in `data/topik-audio`.
  The dry run ends with two warning sections (M7.8, `shortGroups` / `examCoverage` in `scripts/topikImport/plan.ts`): groups holding fewer questions than the range in the file name asks for, and per-exam coverage — how many questions exist and how far the numbering runs unbroken from 1, i.e. how many a mock test of that paper can use. Never errors: a half-typed paper must still import. The parser counts `Heading3` labels and cannot know what *should* be there, so without these a hole is silent until another feature trips over it.
- Add a shadcn component: `npx shadcn@latest add <name>` (then keep tap targets >= 44px)

## Project setup notes
- Path aliases: `@/` → `src/`, `@shared/` → `shared/`, `@db/` → `db/` (in `vite.config.ts`, `vitest.config.ts`, `tsconfig.base.json`). Worker and `db/` code use relative imports.
- TypeScript projects: `tsconfig.app.json` (src + shared, DOM), `tsconfig.worker.json` (worker + shared + db, Workers runtime), `tsconfig.node.json` (config files).
- i18n: `src/i18n/locales/{vi,ko,en}.json`; `vi` is the source of truth for key types. A unit test enforces identical keys and placeholders.
- npm 11 blocks install scripts by default; allowed packages are listed in `package.json` → `allowScripts` (`esbuild`, `workerd`).
- shadcn/ui uses the `cn` package (from shadcn-ui) instead of `clsx` + `tailwind-merge`.
- API: validate with `zv(target, schema)` from `worker/lib/validate.ts`; errors are `{ error, issues? }` (`shared/api/error.ts`). Client calls go through `api()` in `src/lib/api.ts` (validates responses with zod) and TanStack Query hooks in `src/features/<feature>/api.ts`.
- API tests run the Hono app against a real in-memory local D1 via `createTestEnv()` (`worker/test/testEnv.ts`, uses wrangler's `getPlatformProxy`; `@cloudflare/vitest-pool-workers` does not support Vitest 5).
- LLM: `worker/services/llm.ts` (`LlmClient` interface, Gemini via REST `generateContent` + `responseJsonSchema`, `generateStructured()` = zod-validated JSON with one retry, returns `{ data, model }`). Transient errors (429/500/503, network, timeout) are retried 3× with backoff 1s/3s/9s ± 25 % jitter (`worker/services/llmRetry.ts`), then `LLM_FALLBACK_MODEL` gets one try; 400/401/403 fail at once (`rejected` → `ai_rejected`). `ai_cache.model` records the model that answered; the cache key keeps the primary model. The quota is consumed once per cache miss, never per retry. Tests inject `fetch`/`sleep` into `createLlmClient(env, opts)`. Enrichment prompt in `worker/services/enrichPrompt.ts`: bump `ENRICH_PROMPT_VERSION` when the prompt or output schema changes (it is part of the `ai_cache` key).
- Content sanity check (M2.11): `generateStructured()`'s 4th, optional arg `validateContent(data) => string[]` runs once the JSON schema parses; a non-empty result shares the schema's one-retry budget, but — unlike a schema failure — a content problem still present after the retry does **not** throw: the data is returned as-is for the caller to filter. `worker/services/contentCheck.ts` has the actual script checks (`checkKoreanText`/`checkEnglishText`/`checkVietnameseText` + the higher-level `checkSentence`/`checkGlosses`/`checkPhrase`/`checkEnrichment`/`checkSentenceCheck`/`checkPhraseFill`); callers (`enrich.ts`'s `finalizeEnrichment`/`finalizePhrases`, `customItem.ts`'s `finalizeSentenceCheck`/`finalizePhraseFill`) re-run the fine-grained checks on the final data and **drop** just the bad example/phrase/suggestion (logged, never saved) — a required, non-droppable field (e.g. a word's own gloss) is only logged, kept as-is. A sentence's own-language translation field is never checked (the LLM is told to leave it "", the server discards whatever placeholder it actually used). `npm run scan-llm-content` is a read-only report of existing data the checker would flag.
- The Worker app is built by `createApp({ makeLlm, makeTts })` (`worker/app.ts`). `getPlatformProxy` loads `.dev.vars` (real keys), so in tests **always** build the app with `testApp({...})` from `worker/test/testEnv.ts` (paid clients default to null) and inject fakes (`worker/test/fakeLlm.ts`, `fakeTts.ts`). Never call `createApp()` directly in a test: it would use real Gemini/Azure.

Audio is served by `GET /api/media/audio/...` with immutable cache headers; the client plays it through the shared player in `src/features/audio/player.ts`.

- PWA (M2.2): `vite-plugin-pwa` `injectManifest`; the service worker is `src/sw.ts` (own tsconfig `tsconfig.sw.json`, WebWorker lib) with request rules in `src/pwa/swRoutes.ts`. Media cache-first (800 entries, 60 days, Range requests), other `/api` network-only, navigation network-first with the precached shell as the offline fallback, never cache redirects/non-200. Manifest link uses `crossorigin="use-credentials"` (Cloudflare Access). UI in `src/features/pwa/` (`UpdateBanner`, `ConnectionBanner`, `InstallCard`). `api()` goes through `apiFetch` → on a network error `src/lib/accessSession.ts` probes `/api/health` (`redirect: "manual"`): `opaqueredirect` → reload once (Access session expired), else the "Connection lost" banner. **Nothing that can fail may stand between a new worker and activation (M7.4).** `install` copies only the shell (`index.html` + icons, `isShellPath`), file by file through `Promise.allSettled`, with the whole function wrapped in `.catch()`; hashed CSS/JS are runtime-cached (`isHashedAsset`, `CacheFirst`, `ASSET_CACHE`) and `activate` warms them best-effort, then deletes every cache that is not one of its own four. **Never** hand `self.__WB_MANIFEST` to `precacheAndRoute`: it fails the install when any single entry fails, and one transient 500 on one stylesheet left a phone stuck on the previous build (the second such incident; see `SPEC.md` §11 M7.4, and `src/pwa/swLifecycle.test.ts` guards it). Static assets must 404 rather than return HTML: `wrangler.jsonc` has **no** `not_found_handling`, so an unmatched path reaches the Worker, where `spaFallback` (`worker/app.ts`) answers 404 for a path whose last segment has an extension (`shared/staticPath.ts#isStaticFilePath`) and `index.html` otherwise — a shape rule, never a route list. A new service worker **activates immediately** (`self.skipWaiting()` on `install` + `clientsClaim()`, `registerType: "autoUpdate"`): activation must never depend on the app being able to render a button, or a shell that fails to mount leaves the old worker serving its own stale precache with no way out on a phone (the M7.2 production white screen: old `index.html` + an asset hash from the previous deploy → `Cannot read properties of null (reading 'useSyncExternalStore')`). The *reload* is still the user's choice — `UpdateBanner` passes `onNeedReload`, which stops vite-plugin-pwa from reloading by itself, so an update cannot interrupt a review/TOPIK session; ignoring the banner is safe because the next launch loads the new shell. Navigation is network-only while online (`shouldSkipNetwork`), with the precached shell as the fallback after `NAVIGATION_TIMEOUT_SECONDS` = 15 s or when offline — a slow phone network must not be enough to bring an older deploy's HTML back. Update checks run hourly **and** on `visibilitychange` (a phone resumes the app instead of reloading it, and background timers are throttled). Settings shows `BuildInfo` (`__BUILD_ID__` from `vite.config.ts` + the service-worker state from `swState.ts`) so a deploy can be verified without developer tools; a "waiting to activate" state there means this bug is back, and `src/pwa/swLifecycle.test.ts` guards the lifecycle in CI. Icons: `python scripts/make-icons.py`.
- **A shared passage, and one question's own boxed sentence (M7.23):** a reading question that asks *where* a given sentence belongs carries that sentence at the end of its own stem cell, after a `<보 기>` line — the convention questions 39-41 of a real paper already use. It must stay separable, because the question sharing that passage (`CHUNG ĐOẠN`) inherits the stem and would otherwise show a sentence that is not its own. `splitBoxedSentence()` (`shared/topik.ts`) is the single place that knows where the passage stops; `inheritStem`, `driftNotes` and the client's `sharedStem` all go through it, and `ownStemBesideShared()` keeps the box with its question when the group drew the passage once. Never put the sentence at the top of the stem cell, and never in `instruction` (which renders bold everywhere — it would read as part of the prompt). SPEC §11 M7.23 has the reasoning.
- **Two files, one question, one run (M7.25):** `duplicateKeys` (`scripts/topikImport/plan.ts`) refuses a run where two parsed files produce the same `(section, exam, number)`, naming both files — before the scope guard, the backup, any write, and before `--diff` prints a table built from two files compared against one row. This is the cost of `CANONICAL_EXAM`: a block file and the whole paper now resolve to the same exam **on purpose**, so an unfiltered `--force --section reading` had both of them writing the same rows, last one winning silently, and the block files are the worse copy. Limit such runs with `--file` (and read the printed `N of M file(s)` — `--file TOPIK_II_Test` matches 8 reading papers, not 7, because 35회 is one of them).
- **`CANONICAL_EXAM` (M7.23, `worker/services/topikImport.ts`):** two source names for one real exam (`8DeOfficial-35회` → `OfficialTest-35회`), applied where the label is built and reported once per run. It exists because the skip-if-exists check is keyed on `(section, exam, number)`, so without it an ordinary `--apply` — no `--force` needed — re-inserts the same questions under the other name. **It is not another `FIXED_NUMBER_INSTRUCTION`** (the patch table removed in M7.7): that one held a second source of truth for something the Word file must state, this one holds a fact *between* files that no file can state. Add a line only after comparing stems and proving two labels are the same paper.
- **What counts toward the schedule (M7.24):** an answer moves FSRS **iff the question was due** (a question with no card has never been answered, which counts). Decided per question by the **server**, in `POST /topik/attempts`, from `isDueNow()` (`worker/services/topikScheduling.ts`) — the same function the session builder orders by. The client used to send `schedule`; that field is gone from the API, because a client bug or an old build on a phone could otherwise write FSRS state for questions that were not due. `mode=all` now only means "also serve questions that are not due" — a due question answered in such a session counts, which is a deliberate change from M7.2. `GET /topik/session` returns `counts_toward_schedule` per question for the screen's label and banner; it is **display only** and the server decides again when the answer arrives.

## Workflow for every task

## Coding rules
- TypeScript `strict`; no `any` (use `unknown` + zod parsing).
- Validate every API input and every LLM output with zod. LLM output must be strict JSON. On invalid output: retry once, then return an error.
- **No hard-coded UI strings.** Everything goes through i18n (`vi`, `ko`, `en`).
- Put Korean text (incl. Hanja) in elements with `lang="ko"` and use Noto Sans KR.
- Every `<img>` of a study item has alt text (its gloss) and is lazy-loaded in lists; show the item's emoji while `image_status` is `pending` or `failed`.
- Mobile-first layout; tap targets ≥ 44 px; check every screen at 375 px width.
- Feature code lives in `src/features/<feature>/`; shared UI goes in `src/components/`.
- Keep the Worker stateless; all state lives in D1/R2.

## Database rules
- Schema lives only in `db/schema.ts`. Change it, then generate a migration with drizzle-kit.
- **Never edit a migration that has already been applied.** Create a new one.
- Ask before any schema change that drops or renames columns.
- Store ts-fsrs `Card` and `ReviewLog` fields exactly as the library defines them.
- `review_logs` is append-only. Its `card_id` becomes NULL when a card is deleted; use `review_logs.lang` for per-language counts.
- Words vs phrases (option A): `cards.word_id` / `examples.word_id` always hold the **root word**; `phrase_id` is set for phrase rows (NULL = the word itself). Filter word-only rows with `phrase_id IS NULL`.
- Hand-written triggers live in the migration SQL (`0002_phrases.sql`); drizzle-kit does not know about them. `db/migrations.test.ts` runs all migrations and checks that the triggers exist and work. If a later migration rebuilds `cards`, `examples` or `phrases`, recreate the triggers there.
- Before applying migrations locally: stop the dev server, export the DB into `backups/` (gitignored) and compare row counts before/after.

## Cost rules (free tiers)
- **Cache first** for every paid call: TTS audio (R2 key = hash of lang + voice + text), LLM responses (`ai_cache`).
- Never regenerate media that already exists.
- **Images (Workers AI):** primary model `flux-2-klein-4b` (512×512, ≈ 26 Neurons), fallback `flux-1-schnell` (≈ 58 Neurons, no seed, 1024×1024). Content-addressed R2 key = sha1(model + full prompt + style version + nonce + size) (nonce: "0" first, random per Redraw; flux-1-schnell has no seed, see SPEC F3). Check R2 before calling `env.AI`. The fixed style suffix (`flat vector illustration, bright colors, simple shapes, plain background, no text, no letters, family-friendly, safe for children`) lives in one constant (`IMAGE_STYLE` in `worker/services/imagePrompt.ts`) with `IMAGE_STYLE_VERSION`; changing it means bumping the version, never silently redrawing existing images.
- `defaultImageAi(env, requestUrl)` returns the AI binding when present, the fake provider only on a local host without the binding, else null — production can never draw fake images (tested in `worker/routes/imageProvider.test.ts`). Image generation after saving runs with `waitUntil` (never inside the save request; ~30 s limit, stalled items are taken over after 2 min). Redraw / Try again / lazy examples / backfill draw inside their own request. Always idempotent: a retried job finds the existing R2 object and only updates the row.
- Image quota: `usage_daily` service `image`, `IMAGE_DAILY_QUOTA` = 60/profile/day **and** `IMAGE_FAMILY_DAILY_CAP` = 100/day family-wide (both in `shared/image.ts`; change only there, measure Neurons in the dashboard first). Count only real `env.AI` calls; R2 hits are free, and **only a drawing that actually succeeds is billed** (M2.9): a model call that errors refunds its unit at once (`refundImageQuota` in `worker/lib/quota.ts`) — the check-then-consume step (`consumeImageQuota`) stays atomic, so a failed attempt still cannot let two concurrent requests take the same last unit. A skipped draw (`quota: true`) shows `ImageQuotaNotice` (M2.8; reset = UTC midnight, formatted in the viewer's device time via `src/features/images/quotaReset.ts`) everywhere a draw button exists.
- Workers AI account-wide exhaustion (M2.9): error **4006** means the account's own daily free Neuron allocation (10,000/day, separate from our `usage_daily`) is used up — detected by `isProviderExhaustedError()` in `worker/services/imageModels.ts`. `drawClaimedItem` (`worker/services/imageJobs.ts`) then stops at once (no fallback model, no further items in the batch), leaves the item `none` (never `failed`, so it stays retryable), and returns `providerExhausted: true` end to end (`ImageState.provider_exhausted` / `BackfillResponse.provider_exhausted`), shown as its own banner (`ProviderExhaustedNotice`, distinct from `ImageQuotaNotice`). A module-scoped flag (`isProviderExhausted()` / `markProviderExhausted()`, 10-minute window, `resetProviderExhausted()` for tests) makes `drawAfterSave()` (`worker/routes/words.ts`) skip starting the background job while recently exhausted — best-effort only (per-isolate, not durable), Workers AI's own error stays the source of truth.
- Uploads ("My photo") are resized in the browser to ≤ 512 px WebP before upload; the Worker re-checks type and size and never re-encodes.
- Enforce daily quotas per profile through `usage_daily` (pronunciation, LLM, TTS).
- Batch jobs (e.g. TTS for a whole deck) go through Python scripts in `scripts/`, not through the UI.

## Don'ts
- Don't change the tech stack, folder structure or data model without asking.
- Don't implement features that are not in `SPEC.md` ("nice to have" ideas → suggest them instead).
- Don't remove or skip failing tests to make the build pass.
- Don't write large files in one go. Split them into components or modules (< ~250 lines each).

## Lessons learned
- **D1 refuses a statement binding more than 100 parameters**, and the limit is per *statement* — a `db.batch()` of many single-row statements is fine. A multi-row INSERT binds columns x rows, so the ceiling is reached by data growing: a mock test of 12 questions bound 84 and worked, 20 bound 140 and returned 500 every time. Route every multi-row INSERT and every unbounded `IN (...)` through `worker/lib/d1Chunk.ts` (`chunkForD1` / `writeInD1Chunks` / `readInD1Chunks`) instead of remembering the number. The suite missed it because every mock-test API test built a **3-question** paper: for a feature whose real size is known (a TOPIK paper is 50 questions), at least one test has to run at that size. Full write-up and the audit of every bulk statement in `SPEC.md` §11.
- **A display decision with more than two branches goes in a pure function, not in JSX.** Two M6.4 bugs reached a real sitting on a phone for the same reason: the rule was an expression (`viewing ?? tapePosition`, and a three-deep ternary for a picture option's border), so there was nothing for a test to call. Naming the states (`pictureOptionState` → `"correct" | "wrong" | "dimmed" | "chosen" | "idle"`; `shownPosition`) is what surfaced the missing branch: "chosen but not graded" exists only in a mock test, since practice grades on the tap. Write the function, let JSX map its result to classes. Full write-up in `SPEC.md` §11.
- **Windows: always build from the real path casing.** `cd d:\dev\lingo-family` works (Windows ignores case) but Vite keys modules by the id string, so `root` keeps the typed casing while the resolver's realpath returns `D:\DEV\lingo-family` — the same file enters the graph twice and the bundle ships **two copies of React** (`Cannot read properties of null (reading 'useSyncExternalStore')`, white screen on production only; local builds happened to use the right casing). Fixed by pinning `root` + the `@`/`@shared`/`@db` aliases to `realpathSync.native(import.meta.dirname)`, and `scripts/viteGuards/buildIntegrity.ts` now fails the build on any file seen under two ids (healthy client graph: 2438 modules / ~886 KB; duplicated: 4478 / ~1.05 MB — the module count is the reliable signal, the byte size only grows 1.19×). For any "works locally, broken on production" report, first download production's JS and diff it byte for byte against a local build with `__BUILD_ID__` masked: that separates "wrong thing served" from "wrong thing built" before any theorising. Full write-up in `SPEC.md` §11.
- `npx shadcn add <x>` may ask to overwrite `button.tsx`: answer **no** (`echo n | npx shadcn add <x>`), it has custom 44px sizes. Check new components for hard-coded English strings (e.g. "Close" in `dialog.tsx`).
- Don't `disable` an input while checking it asynchronously (it loses focus); use `readOnly`.
- Gemini can return 503 "high demand" or take 30s+ under load. The shared client retries (see LLM above) within a 100 s budget, 45 s per attempt; set `LLM_FALLBACK_MODEL=gemini-3.5-flash-lite` in `.dev.vars` so a busy primary falls back. The UI shows "AI is busy" + a Try again button (`isRetryableAiError()`); a button inside a `<form>` needs `type="button"` or it also submits the form.
- Homonyms (e.g. 사과 = apple / apology) made the LLM mix meanings with one Hanja; the prompt now asks for the most common meaning only.
- drizzle's `db.batch()` on D1 cannot run raw `db.run(sql\`...\`)` statements with parameters (`stmt` is undefined). For raw SQL batches use the D1 API: `env.DB.batch([env.DB.prepare(...).bind(...)])`.
- `drizzle-kit generate` asks interactively when a column is renamed (it cannot be answered here). Write a custom migration instead: `npx drizzle-kit generate --custom --name <x>`, put the SQL in it, then copy the table definitions of a reference snapshot (generate the current schema into a temp `out` dir) into the new `meta/000N_snapshot.json`, keeping its `id`/`prevId`; `npm run db:generate` must then report "No schema changes". Test the migration in `db/migrations.test.ts`.
- Workers AI (`env.AI`) has no local simulator: it always runs on Cloudflare, so `npm run dev` needs `npx wrangler login` once (otherwise the remote proxy session fails). Tests call `getPlatformProxy({ remoteBindings: false })` so they never need login or touch Workers AI.
- Scripts that need Worker code (TypeScript) run through `benchmarks/run.mjs` (Vite's `runnerImport`, no extra TS runner).
- `getPlatformProxy().env` bindings are not enumerable: `{...env}` / `Object.assign({}, env)` drops them; use `Object.create(env)` to add overrides.

- **Never paste a secret with Ctrl+V in `cmd`**: it pasted 1 control character, so `LLM_API_KEY` had length 1 and Gemini answered with an empty-body 400. Set secrets with `npx wrangler secret bulk <file.json>` from a temporary JSON file **outside the repo** (`{"LLM_API_KEY": "..."}`), then delete the file. The LLM client trims whitespace but cannot repair a wrong value.
- Gemini rejects requests from some Cloudflare data centers: Hong Kong (`HKG`) serves Korean users ("User location is not supported"). Keep the Placement setting in `wrangler.jsonc` (`gcp:asia-northeast3`, Seoul); **do not remove it**. `request.cf.colo` shows where the user entered, not where subrequests leave from; `https://www.cloudflare.com/cdn-cgi/trace` fetched from the Worker shows that. Settings → "AI status" shows which model answered last (primary or fallback).
- A test that reuses a `term`/`image_prompt` already drawn successfully by an earlier test in the same file hits the R2 cache (content-addressed key) and silently skips the fake AI call — `fake.calls` comes back empty/short with no error. R2 (unlike D1 tables) is **not** cleared in `images.test.ts`'s `beforeEach`, so each test there needs its own term/prompt never used elsewhere in the file.
- `npm run dev`'s local D1 does **not** auto-apply new migrations on start — run `npm run db:migrate:local` after `npm run db:generate`. Forgetting it does not error loudly: a SELECT on the missing column silently returns the **column name itself as a string literal** for every row (SQLite's legacy double-quoted-identifier fallback: an unresolved `"colname"` is read as a string literal instead of erroring), which then passes zod validation if the type happens to match and only shows up as wrong data in the UI.
- **Flaky tests = too many Miniflare instances at once.** Every test file that uses `createTestEnv()` / `getPlatformProxy` starts its own workerd process; with all of them in parallel on Windows about 1 run in 3 failed with `connect EADDRINUSE 127.0.0.1:<port>` (unrelated tests failing: profiles, media 404, migrations). `vitest.config.ts` therefore has two projects: `unit` (src, shared, scripts, benchmarks; parallel) and `worker` (worker, db; `maxWorkers: 2`, run after `unit`). Put new D1/R2 tests under `worker/` or `db/`, never in `src/` or `shared/`. If `EADDRINUSE` ever comes back, set `maxWorkers: 1` for `worker`.
- `scripts/**/*.ts` compiles under `tsconfig.node.json` (`types: ["node"]`, no `worker-configuration.d.ts`), so a script that imports a `worker/` function whose signature names an ambient Workers type (`R2Bucket`, `D1Database`) fails to typecheck even behind a cast (`as unknown as R2Bucket` still needs to resolve the name `R2Bucket`, which doesn't exist in that project). `scripts/assignCreator` already does this for D1 (`type D1Like = {...}`); `scripts/topikImport/run.ts` does the same for R2 (`type R2Like`, plus its own small copy of `storeUploadedImage`) instead of importing `worker/services/imageUpload.ts` directly.
- **A clip's questions are one group (M7.5):** `group_id` = `segment_id ?? question.id`, carried on the practice question and the sitting question; `src/features/topik/groups.ts` groups consecutive questions by it, and a screen renders one group (`TopikQuestionCard` / `TopikTestQuestionCard` per question, one clip player above). `buildTopikSession` takes **whole groups** and lets the last overshoot `session_size`. The transcript/explanation withholding lives in the API, never only in the UI: `POST /topik/attempts` takes `group_pending` (send it while any sibling is unanswered) and returns `group_reveal` for the whole group on the answer that completes it; `GET /topik/questions/:id/reveal` is the deliberate give-up, read-only (no attempt, no card). `sessionState.ts` has three states — `answered`, `skipped` (answerable later) and `given_up` (locked for the session); `recordAnswer` refuses to overwrite the last, which is what stops an answer typed with the transcript open from reaching FSRS.
- **The Word file is the only source of a question's instruction (M7.7).** `FIXED_NUMBER_INSTRUCTION` used to force the "[3~4] …" line by question number, because several source files carried the wrong "[1~2] …" line there or none at all; the files were fixed instead and the table is gone. Only `FIXED_NUMBER_BLOCK` remains, and for a different reason: one real file covers questions 1-4 at once, so `block` cannot come from its name ("1~4") and is decided by the number. When adding a block instruction to an existing file, type it **inside the first question of its block**, never between two questions — a paragraph between them belongs to the one *before* it, so the line would apply from the wrong question on (M7.3's "applies to this question and the rest of the group"). The way this was verified before removing the patch is the pattern to repeat for any import change: parse every file, compare every column against production row by row, and require the diff to be exactly what was intended — 52 instruction cells and nothing else, then 0 after the removal.
- **An underline counts only on real text (M7.10):** `hasUnderline` looks for `<w:u>` inside the `<w:rPr>` of a `<w:r>` whose text is not blank — never anywhere in the subtree. Word keeps the end-of-paragraph mark's formatting in `<w:pPr><w:rPr>`, where an underline is invisible (nothing to draw under), and counting it reported every option of a question as underlined. Any rule that reads formatting out of a `.docx` has to say which *text* carries it; "the tag exists somewhere below" is not the same thing.
- **One answer rule for both sections (M7.9):** the `N(N)` label **is** the answer, everywhere; the underline is only read back against it. Every underline anomaly — none, several, or one that disagrees — is a **warning naming both numbers** ("answer label says option 2, but option 4 is underlined"), never a refusal, because these files are typed from PDFs and formatting bleed is routine. The one hard error left is a **missing label**: no label, no answer, and nothing is ever inferred from an underline. Reading used to treat the underline as authoritative and refuse the question on a disagreement; `parseTopikDocument` no longer takes a `section` at all, since nothing in the parse depends on it any more. Four-picture options are exempt from the "no underline" warning — nothing can be underlined on a picture.
- **TOPIK Word conventions (M7.3), in the file itself:** a question's own question line is a paragraph `HỎI: <text>` (also `HOI:`, any case) — it is appended under the group's block instruction in the one `instruction` column, so the block's `(각 2점)` still sets the points and the three render sites use `whitespace-pre-line` (the manual edit form is a textarea for the same reason). The second question of a pair is marked `CHUNG ĐOẠN` and leaves its **stem cell empty**: `inheritStem` takes the transcript from the question before, so the recording's transcript exists once, not twice (its own stem still wins, and one that contradicts the shared clip is a warning). A `[N~M] …` block instruction found inside a question applies to that question and the rest of its group — files really do start a new block part way through one. A stem line that reads like an instruction (`commandLikeStemLines`: ends in 고르십시오/답하십시오/쓰십시오/…) is a **warning** quoting the line — in the listening layout the transcript is plain paragraphs, so a question line missing its prefix lands in the transcript and nothing can prove it was not something a speaker said; match only those instruction verbs, since "anything ending in 십시오" flagged 11 real reading stems (notices, medicine labels). **Any paragraph inside a question that nothing used is reported verbatim** (`ParsedItem.ignored`): before/between the question's parts → a hard error naming the question and quoting the line (the question is not imported); after the four options → an import-report line only, because that is the file author's own glossary area. Never add a code path that drops typed-up content without saying so — see the lesson below.
- **TOPIK import, real file shapes (M6.1):** a `.docx`'s `word/document.xml` is parsed with `fast-xml-parser`'s `preserveOrder: true` (the default object-keyed mode drops sibling order between different tag types, e.g. interleaved `<w:p>`/`<w:tbl>` — fatal here since the whole parse walks the body in document order). One `Heading1` ("유형K: 문항 N~M" or "문항 N") covers several `Heading2` exam groups ("연습K", sometimes "(XX회)" suffixed); the instruction paragraph repeats once per `Heading2`, right before its first `Heading3`. A question is either a 2-column table (row 0 = stem, rows 1–2 = the 4 options, correct one **underlined**, sometimes also bold) or an image stem + exactly 4 `ListParagraph` options (correct one underlined only, no bold) — a stray trailing "vocab note" paragraph after the 4 options must not become a 5th option. The real question `number` is `fileNameBlockStart + ((position in its exam group − 1) % blockSize)`; the "-N" suffix on the `Heading3` label usually agrees but is only a cross-check (one real file had a typo'd `Heading1`, `"문항 9"` vs. the file name's `10`). A plain `pStyle` truthiness check for "is this paragraph a new heading" is wrong — `ListParagraph` also has a `pStyle` and gets mistaken for one, silently truncating every item to zero options; check the style value is actually `Heading1`/`2`/`3`.
- **TOPIK exam label must key off the real exam round, not the file's own group counter (M6.1 bug, caught after a real production import):** `8DeOfficial`'s Cau09/Cau10 files have one `Heading2` group ("연습1") covering several different real exam rounds (36회, 37회, 41회, …), each as its own `Heading3` item — labeling by group text alone collapsed all of them into one `exam`, and the unique `(section, exam, number)` constraint then silently skipped 12 of 14 image questions as "already existed" (they looked like duplicates of the same `number` under the same `exam`, but were genuinely different questions). The first fix (`exam = source-연습groupIndex[-round]`) stopped that collision but still gave the *same* real exam a *different* label per file (`8DeOfficial-연습1-36회` from Cau09 vs. `8DeOfficial-연습2-36회` from Cau01_04) — wrong, because reassembling one complete real exam into a mock test later means every question from that exam must share one label regardless of which file/block happened to carry it. Final rule (`worker/services/topikImport.ts`): when an item's label names a round, drop the group index entirely and use `source-round` only; fall back to `source-연습groupIndex` only when there is no round at all (Yonsei files) — relying on the group counter restarting at 1 in every file to correctly merge matching groups across files. A second bug in the same release: image refs inside the docx zip are at `word/media/imageN.png`, not `media/imageN.png` — the missing `word/` prefix made every image lookup fail silently (parsed as "has an image" but saved with `image_key: null`, no error). Fixed by prefixing the path and by adding `scripts/topikImport/plan.ts#checkQuestionImages` (dry-run-safe: resolves + validates every image reference up front and reports a question as an error, never silently, if any reference can't be found or fails validation).
- Running `wrangler d1 migrations apply --local` while `npm run dev` is running against the same local D1 can fail with an opaque Miniflare "internal error" (both hold the same SQLite file) — stop the dev server first.
